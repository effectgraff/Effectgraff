# Проверка EffectGraff.ru — 19 августа 2026

## Итог

Публичный сайт доступен по HTTPS, `www.effectgraff.ru` отвечает `HTTP/2 200`, изображения и WAV-аудио доступны, главная страница отображает портфолио, CTA, VK-карточку и бриф. Однако есть два технических замечания: корневой HTTPS проходит через промежуточный редирект на HTTP перед возвратом на HTTPS, а `/.well-known/security.txt` на публичной Yandex-копии отвечает `404`.

## Что нужно исправить

### 1. Убрать промежуточный HTTP-редирект

Сейчас `https://effectgraff.ru` возвращает сначала `301` на `http://www.effectgraff.ru/`, после чего второй редирект переводит на `https://www.effectgraff.ru/`. Это функционально, но хуже для безопасности, скорости и SEO, чем один прямой переход на HTTPS.

Целевой результат: один ответ `301` с `https://effectgraff.ru` на `https://www.effectgraff.ru/`. Исправление находится в настройках переадресации REG.RU: источник должен быть HTTPS-корень, а назначение — HTTPS-версия `www`; HTTP→HTTPS следует включить отдельно.

### 2. Опубликовать security.txt

`https://www.effectgraff.ru/.well-known/security.txt` отвечает `404`, хотя файл есть в исходном проекте. Вероятная причина — при копировании в Yandex не был создан префикс `.well-known`.

Нужно загрузить файл в объект:

```text
s3://www.effectgraff.ru/.well-known/security.txt
```

с `Content-Type: text/plain`. Сам файл не должен содержать секретов; достаточно адреса для ответственного сообщения об уязвимостях и ссылки на политику.

### 3. Реальный тест аудиолупа

Файл доступен, а production JS содержит HTML-элемент `audio` с правильным WAV-путём. В браузерной консоли ошибок после клика не появилось. Однако фактический звук зависит от разрешений браузера и устройства, поэтому один раз проверьте кнопку на iPhone и Mac после принятия или отклонения cookie-настроек.

## Лидогенерация

Бриф формирует письмо через почтовую программу; он не отправляет данные на сервер. Для менеджера это снижает инфраструктурный риск, но путь конверсии нужно проверять тестовым заполнением без реальных персональных данных. Отдельно следует убедиться, что на мобильном устройстве открывается почтовый клиент и заполненное письмо содержит корректного получателя, тему и поля заявки.

## Итоговый приоритет

Сначала исправить прямой HTTPS-редирект и загрузить `security.txt`. Затем выполнить ручной тест формы на iPhone и Mac, проверить аудиолуп с разрешением звука и убедиться, что письмо открывается с правильным адресатом. После этого сайт можно считать технически готовым к регулярному органическому продвижению; поисковые позиции и поток лидов всё равно требуют наблюдения, контента и ручной обработки обращений.
