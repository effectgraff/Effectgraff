# Яндекс Метрика для EffectGraff.ru: точная настройка без ПДн

## Важное правило

В Метрику передаём только факт обезличенного действия и фиксированный идентификатор события. Не передаём имя, телефон, email, город, бюджет, текст брифа, URL с параметрами формы, содержимое письма, IP, cookie-значения или любой другой идентификатор человека.

> Цель аналитики — понять, какой канал приводит к действию, а не собирать содержание заявки.

## 1. Создание счётчика

Откройте [Яндекс Метрику](https://metrika.yandex.ru/) и создайте один счётчик для:

```text
https://www.effectgraff.ru
```

Рекомендуемые параметры счётчика:

| Поле | Значение |
|---|---|
| Имя | `EffectGraff.ru — лидогенерация` |
| Сайт | `https://www.effectgraff.ru` |
| Часовой пояс | `Europe/Moscow` |
| Вебвизор | Включать только после отдельной оценки privacy-настроек; для минимального режима можно оставить выключенным |
| Электронная коммерция | Выключить |
| Отправка данных форм | Выключить |
| Дополнительные параметры URL | Не передавать данные формы в URL |

После создания скопируйте числовой **ID счётчика**. В коде он обозначается как `COUNTER_ID`; вместо него нужно подставить реальный номер, например `12345678`.

## 2. Cookie-согласие и загрузка счётчика

Счётчик нельзя загружать до того, как посетитель явно согласился на необязательную аналитику. Кнопка «Отклонить» должна оставить Метрику выключенной. Не использовать скрытое согласие, предварительно отмеченную галочку или блокировать сайт до согласия.

Псевдологика должна быть такой:

```text
если аналитическое согласие явно принято:
    загрузить счётчик
иначе:
    не загружать счётчик
```

Если в текущей версии сайта уже есть cookie-баннер, не создавайте второй баннер. Проверьте, что именно кнопка принятия аналитики запускает загрузку Метрики, а отказ не запускает её.

## 3. Цели в интерфейсе Метрики

В Метрике откройте **Настройки → Цели → Добавить цель → JavaScript-событие**. Для каждой цели укажите название и идентификатор ровно так, как в таблице.

| Название цели | Идентификатор JavaScript-события | Что означает |
|---|---|---|
| Валидный бриф отправлен | `brief_submit_valid` | Форма прошла проверку и сформировала обращение |
| Клик по телефону | `phone_click` | Посетитель нажал телефонную ссылку |
| Клик по email | `email_click` | Посетитель нажал email-ссылку |
| Клик по VK | `vk_profile_click` | Посетитель открыл официальную группу VK |
| Обсудить стену | `project_cta_click` | Нажат CTA перехода к контакту или брифу |
| Открыт архив | `archive_open` | Посетитель открыл портфолио/архив |
| Переключён язык | `language_switch` | Посетитель переключил RU/EN |

Для целей используйте тип **JavaScript-событие**, а не поиск по URL, если действие не создаёт отдельный безопасный URL. Не создавайте цели по email, телефону, имени или содержимому query-параметров.

## 4. Точные вызовы событий

После загрузки Метрики сайт должен вызывать фиксированные события. Вызов выполняется только после пользовательского действия и только с постоянным идентификатором.

```javascript
// Заменить COUNTER_ID на реальный числовой ID счётчика.
function trackEffectGraffGoal(goalId) {
  if (typeof window.ym !== "function") return;

  const allowedGoals = new Set([
    "brief_submit_valid",
    "phone_click",
    "email_click",
    "vk_profile_click",
    "project_cta_click",
    "archive_open",
    "language_switch",
  ]);

  if (!allowedGoals.has(goalId)) return;
  window.ym(COUNTER_ID, "reachGoal", goalId);
}
```

В реальном коде `COUNTER_ID` должен быть числом, например:

```javascript
window.ym(12345678, "reachGoal", "phone_click");
```

Нельзя делать так:

```javascript
// Нельзя: передаёт телефон в аналитику.
window.ym(12345678, "reachGoal", phoneNumber);

// Нельзя: передаёт email или текст формы.
window.ym(12345678, "reachGoal", emailValue, { email: emailValue });

// Нельзя: передаёт поля брифа как параметры цели.
window.ym(12345678, "reachGoal", "brief_submit_valid", formData);
```

## 5. Где размещать события

| Действие в интерфейсе | Событие |
|---|---|
| Успешная клиентская валидация брифа и формирование письма | `brief_submit_valid` |
| Нажатие на `tel:` | `phone_click` |
| Нажатие на `mailto:` | `email_click` |
| Нажатие на ссылку `https://vk.ru/effectgraff` | `vk_profile_click` |
| Нажатие CTA «Обсудить стену» | `project_cta_click` |
| Открытие архива или портфолио | `archive_open` |
| Переключение RU/EN | `language_switch` |

Событие `brief_submit_valid` означает только успешное прохождение проверки и подготовку обращения. Оно не должно означать, что письмо доставлено или что заказ заключён. Для последнего статуса нужен отдельный учёт менеджера.

## 6. Рекомендуемые отчёты

Создайте в Метрике сегменты и отчёты по источнику перехода, языку, типу устройства и странице события. Не добавляйте в отчёты личные поля. Основная последовательность анализа:

```text
источник → просмотр проекта → project_cta_click → brief_submit_valid → квалифицированный лид в CRM
```

Для менеджера достаточно еженедельной таблицы: дата, источник, событие, URL страницы, язык, устройство, стадия обработки. Телефон и email хранятся только в предназначенном для заявок почтовом ящике или CRM, а не в Метрике.

## 7. Тестовый чек-лист

| Проверка | Ожидаемый результат |
|---|---|
| Открыть сайт и отклонить аналитику | Запросы Метрики не появляются или счётчик не инициализируется |
| Открыть сайт и принять аналитику | Счётчик загружается после согласия |
| Нажать CTA | В Метрике появляется `project_cta_click` |
| Нажать телефон | Появляется `phone_click`; номер не передаётся как параметр |
| Нажать email | Появляется `email_click`; email не передаётся как параметр |
| Нажать VK | Появляется `vk_profile_click`; URL фиксирован |
| Заполнить тестовый бриф фиктивными данными | Появляется `brief_submit_valid`; содержимое полей в Метрику не уходит |
| Проверить Network/Console | Нет запросов с `name`, `phone`, `email`, `budget`, `city`, `message` |
| Перезагрузить страницу | Состояние согласия сохраняется по выбранной политике |

Для тестового брифа используйте только вымышленные значения, например `test@example.invalid`, и не отправляйте его реальному адресату.

## 8. Что не включать

Не подключать импорт телефонных книг, загрузку CRM-контактов в Метрику, передачу email или телефона в URL, динамические параметры с содержимым формы, скрытые пиксели сторонних сервисов и запись сессий до согласия. Вебвизор и иные расширенные функции включать только после отдельной проверки их privacy-параметров.
